# URL Shortcuts

**Date**: October 15, 2026

## Summary

A shortcut can now open a link as well as an app. An entry with `url:` instead of `file:` makes Karabiner run `open '<url>'`, so `https://…` opens in the default browser and a custom scheme such as `slack://…` opens the app that owns it. `karayaml map <key> <app-or-url>` takes either. Reload now validates every entry first, the generated shell command quotes values safely, and an entry with neither `file` nor `url` is skipped with a warning instead of becoming `open -a ''`.

## Problem Statement

Every rule's command was `open -a '<file>'`, which only opens applications. `open -a 'https://github.com'` fails with "Unable to find application", so a key could not open a page or a deep link, even though the site's FAQ said URLs worked.

### Pain Points

- No way to map a key to a web page or an app's deep link
- The FAQ claimed "You can also open files or URLs", which was not true
- The value was wrapped in single quotes with no escaping, so an app name containing `'` produced a broken command
- `reload`, `map` and `init` wrote the Karabiner config without any check; an entry with an empty `file` became `open -a ''`

## Solution

Added an optional `url` field beside `file` and moved the command and validation into one place (`internal/shortcuts/target.go`), so `save` and `edit` share it.

### Key Components

- **`internal/shortcuts/yaml_struct.go`** -- New `URL` field; both `file` and `url` are `omitempty`, so existing files rewrite unchanged and url entries carry no `file:` line
- **`internal/shortcuts/target.go`** -- New: `NewShortcut()` (a target containing `://` is a URL), `Target()`, `ShellCommand()` with `shellQuote()`, and `Validate()`
- **`internal/shortcuts/save.go`** -- Uses `ShellCommand()`, describes rules as `open <target>`, refuses to write while any entry is invalid (naming all of them), skips entries with neither field with a warning
- **`internal/shortcuts/yaml_file.go`** -- The `edit` loop re-opens the editor on `Validate()` errors; `getDuplicates()` removed
- **`internal/shortcuts/list.go`** -- Tables and the match message show the target; `find` searches files and URLs; `filter by-app` stays apps only
- **`internal/shortcuts/add.go`**, **`cmd/karayaml/root/map.go`** -- `map <key> <app-or-url>`, validated before anything is written
- **`site/src/components/home/{FAQ,ExampleGallery,CLIReference}.jsx`** -- FAQ corrected, a `url:` example, the `map` row updated
- **`internal/shortcuts/*_test.go`** -- The repository's first tests

## Implementation Details

```yaml
- key: g
  url: https://github.com
- key: s
  file: Safari
```

**Commands**: `ShellCommand()` returns `open -a '<file>'` or `open '<url>'`. `shellQuote()` escapes `'` as `'\''`, so `Bob's App` becomes `open -a 'Bob'\''s App'`.

**Validation** reports every problem at once: an unsupported key, both `file` and `url` on one entry, or a `url` without a scheme (`github.com` instead of `https://github.com`). An entry with neither is treated as an intentional placeholder: skipped with `warning: key '<k>' has neither file nor url; skipped`, and it no longer overrides an earlier mapping of the same key.

**YAML**: the file is still written by ghodss/yaml from the JSON tags with sorted keys, so a url entry reads `key` then `url`, and file entries are byte-for-byte what earlier versions wrote.

**Tests** are table tests: quoting, commands, `map` detection, validation, a YAML round trip, and `save` against a temporary home directory, reading back the generated Karabiner rules.

## Benefits

- One key can open a page, a web app or any app's deep link
- App names with quotes work
- Mistakes in `~/.kara.yaml` are reported by name instead of producing broken rules
- No change for existing configs

## Impact

**Users**: `url:` entries and `karayaml map g https://…`. A config with an invalid entry now stops `reload` with a list of what to fix, where it used to write a broken rule.

**Developers**: One place builds and validates commands, with tests around it.

**Files changed**: 6 modified Go files, 1 new Go file, 3 new test files, 3 site components.
